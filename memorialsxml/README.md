# MemorialsXml 1.2.0 — импорт memorials.xml в miniShop3

Самостоятельный CLI-модуль для MODX Revolution 3.2.4-pl, miniShop3 1.14.3-beta2 и PHP 8.5. Источник по умолчанию: https://kukmorstone.ru/bitrix/catalog_export/memorials.xml.

Создаёт новые и обновляет существующие товары по артикулу в выбранном контексте MODX. Переносит дерево категорий, цены, описание, вес, изображения и характеристики. Поддерживает XML на сервере и HTTP(S)-ссылку. Разработан на основе предыдущего импортера ТСС; поставляется отдельно, со своим пространством имён и метаданными. Интерфейс в менеджере MODX и transport-пакет в эту версию не входят.

## Повтор только неудачных изображений (1.2.0)

Сначала проверьте фазу и счётчики. Если фаза ещё `images`, очередь не закончена: продолжайте обычный авторежим. Счётчик `images_existing` также означает успешную обработку, а не пропуск с ошибкой. Идентичные изображения в галерее одного товара не дублируются. В проверенном снимке для уникальных артикулов ожидалось 4 246 ссылок; ещё 114 ссылок относятся к 38 исключённым записям с повторным артикулом.

Когда исходный цикл завершён (`done`/`done_with_errors`), а `failed_images` не пуст, обновите файлы модуля с сохранением `config.php` и позиции в кеше. В Console выполните один раз без `<?php`:

```php
$batchSize = 1;
$maxSeconds = 15;
$imageTimeout = 25;
require MODX_CORE_PATH . 'components/memorialsxml/console-retry-images.php';
```

Дальше Console автоматически обрабатывает сохранённую очередь `retry_images`. Повторяются только URL из `failed_images`; товары не переимпортируются, текущий XML не скачивается заново, успешно обработанные ранее картинки повторно в очередь не добавляются. Начальная очередь дедуплицируется по артикулу/URL. После успешного повтора соответствующая ошибка убирается из текущего списка; история сохраняется в `image_error_history`. Старые ошибки заменяются точной новой причиной, например HTTP-кодом или сообщением процессора.

Показываются `Повтор изображений`, `Успешно при повторе` и последние ошибки. После завершения прохода авторежим останавливается даже при оставшихся ошибках: бесконечного повторения недоступного URL нет. После исправления источника/Media Source можно вручную запустить тот же код ещё раз — он повторит только оставшиеся ошибки. Два оборванных запроса на одном элементе отмечаются ошибкой и не блокируют остальную очередь. Картинки товаров с неустранённой ошибкой импорта данных требуют сначала исправить данные товара.

`imageTimeout` теперь учитывается: прежнее ограничение Console в 10 секунд больше не перекрывает настройку. Значение по умолчанию для обычного режима — 20 секунд; диапазон 1..120 секунд. Сетевой тайм-аут вместе с генерацией миниатюр должен укладываться в лимит вашего PHP/веб-сервера. `maxSeconds` проверяется только между операциями. Не задавайте `resetImport=true` и не очищайте кеш для повтора картинок.

Если ошибок изображений нет, а фотографии отсутствуют на витрине, этот повтор ничего не изменит: потребуется проверить галерею конкретного товара, наличие оригиналов/миниатюр, Media Source и шаблон вывода. Сам по себе более низкий `images_added` не доказывает потерю картинок.

## Автоматическое продолжение в Console (1.1.1)

Используется штатный протокол дополнения Console: `$_SESSION['Console']['completed'] = false` вызывает следующий запрос после завершения текущего. Цикла `while` внутри одного долгого PHP-запроса нет. Доступ к процессору и выполнение PHP остаются под авторизацией установленного Console; дополнительные HTTP-точки входа не создаются.

После обновления файлов модуля с сохранением `config.php` один раз выполните в Console без `<?php`:

```php
$batchSize = 20;
$maxSeconds = 15;
require MODX_CORE_PATH . 'components/memorialsxml/console-auto.php';
```

Дальнейшие порции запускаются автоматически. Оставьте вкладку открытой: работа продолжается запросами браузера, а не фоновым серверным процессом. На `done`, `done_with_errors` или ошибке запуска повторение останавливается. При обрыве HTTP-запроса повторно выполните этот же код: сохранённая позиция используется дальше. Старый флаг повторения и переменная состояния сбрасываются в начале каждой итерации, чтобы ошибка не запустила бесконечное повторение.

Остановка через Console:

```php
$_SESSION['Console']['completed'] = true;
```

После остановки текущая порция может завершиться. Закрытие страницы прекращает новые запросы браузера, но не прерывает уже отправленную порцию. Если закрывали страницу во время автоматического режима, перед выполнением другого произвольного кода Console выполните строку остановки, чтобы сбросить оставшийся флаг повторения. Не запускайте одновременно ручной и автоматический режимы.

Формат позиции совпадает с 1.1.0: существующий цикл продолжится без сброса. В автоматическом режиме `resetImport` всегда выключен. Новый цикл со свежим фидом сначала создаётся однократным ручным запуском с `resetImport=true`, после чего можно снова включить авторежим.

Этот механизм есть в стандартном Console; если ваша модификация Console игнорирует флаг `completed`, автоматическое продолжение потребует проверки её версии. Протокол сверён с `MODX-Club/modx-console`: `processors/exec.class.php` и `console.panel.js`.

## Порционный запуск через Console (1.1.0)

Полный каталог с тысячами изображений не следует обрабатывать одним HTTP-запросом. Версия 1.1.0 добавляет `console-batch.php` и `src/ConsoleBatch.php`: один запуск Console обрабатывает небольшую порцию, сохраняет позицию и возвращает управление. Следующий запуск того же кода продолжает работу. Это ручное продолжение порций, не фоновый процесс и не автоматическое выполнение всего каталога за одно нажатие.

Обновите файлы модуля целиком, сохранив свой `config.php`. В Console MODX 3 вставьте без `<?php`:

```php
$batchSize = 5;
$maxSeconds = 15;
$resetImport = false;
require MODX_CORE_PATH . 'components/memorialsxml/console-batch.php';
```

Выполняйте этот же код повторно, пока фаза не станет `done` или `done_with_errors`. Сначала обрабатываются `products` (товары и характеристики), затем `images` (картинки). Число `batchSize` ограничивает товары или отдельные изображения в соответствующей фазе. Для меньших порций задайте 1..3; максимум 100. Бюджет `maxSeconds` проверяется между операциями и не является жёстким ограничением времени генерации миниатюр.

Позиция, фиксированный XML и ошибки сохраняются в `core/cache/memorialsxml-batch/<идентификатор>/`. Точный путь выводится после каждой порции. Не очищайте кеш MODX во время цикла: это может удалить позицию. Ошибки и последняя начатая картинка записаны в `state.json`; таблицы базы для позиции не добавляются. Между запусками можно закрыть Console и вернуться позднее. Изменение текущего фида поставщика не меняет уже сохранённый снимок.

В версии 1.1 запрос загрузки изображения ограничивался 10 секундами; в 1.2 тайм-аут настраивается через imageTimeout (см. раздел повтора изображений). Если PHP/сервер оборвёт обработку внутри картинки, её позиция остаётся записанной и будет повторена. После двух незавершённых попыток следующий запуск пропустит эту картинку, сохранит ошибку и продолжит. Остальные ошибки загрузки также фиксируются и не останавливают всю очередь. `done_with_errors` означает завершение обхода, а не успешную загрузку всех картинок. Генерация миниатюр в miniShop3 может занимать время сверх сетевого тайм-аута; ограничение nginx/хостинга этим кодом не изменяется.

Чтобы начать новый цикл с актуальным XML, один раз выполните код с `$resetImport = true`, затем верните `false`. Это сбрасывает только позицию/снимок модуля. Товары и изображения магазина не удаляются. Ошибки предыдущего цикла перед сбросом сохраните из `state.json`.

Уже работающий старый полный импорт удерживает ту же MySQL-блокировку. В этом случае новый запуск сообщит, что предыдущий ещё работает. Закрытие вкладки браузера не гарантирует остановку серверного процесса.

Изменения производительности: неизменившиеся категории не сохраняются повторно; CLI-загрузка картинки по умолчанию ограничена 20 секундами (можно задать `image_timeout` в конфигурации). Для автоматического импорта всего каталога без ручного повторения Console по-прежнему используйте CLI/cron.

## Установка и запуск

1. Распакуйте каталог `memorialsxml` на сервере, например `/var/import/memorialsxml/`.
2. Скопируйте `config.example.php` в `config.php`.
3. Укажите `modx_base_path` — абсолютный путь к корню MODX с файлом `config.core.php`; `root_id` — ID существующей корневой категории miniShop3; `manager_user_id` — ID активного пользователя MODX с `sudo=true`.
4. При необходимости укажите шаблоны новых товаров/категорий и контекст. Настройте Media Source miniShop3 для загрузки изображений и генерации миниатюр.

```bash
cd /var/import/memorialsxml
cp config.example.php config.php
# Отредактируйте config.php.

# Проверка всего XML без подключения к MODX:
php import.php --config=/var/import/memorialsxml/config.php --inspect

# План по вашей базе, без записи каталога:
php import.php --config=/var/import/memorialsxml/config.php --dry-run > plan.jsonl

# Пробная запись первых десяти товаров без изображений:
php import.php --config=/var/import/memorialsxml/config.php --limit=10 --no-images > trial.jsonl

# Полный импорт:
php import.php --config=/var/import/memorialsxml/config.php > import.jsonl
```

Для файла на сервере:

```bash
php import.php --config=/var/import/memorialsxml/config.php --source=/var/import/memorials.xml
```

Первую запись выполните на копии сайта. `--limit` ограничивает число обрабатываемых товаров с уникальными артикулами; всё дерево категорий обрабатывается целиком, весь XML проверяется перед записью. План не вызывает процессоры сохранения и не скачивает изображения. Инициализация MODX может создавать его системный кеш.

Запуск через cron: та же команда с абсолютными путями к PHP/конфигурации и перенаправлением stdout/stderr в журнал. CLI-пользователь должен иметь доступ к MODX, временному каталогу и медиахранилищу. Секретов в конфигурации самого модуля нет: подключение к базе берётся из MODX. Composer для модуля не требуется.

Расширения PHP: XMLReader, SimpleXML, mbstring, cURL, fileinfo, а также PDO MySQL и расширения для изображений, необходимые вашей установке MODX/miniShop3. PHP CLI должен соответствовать PHP сайта.

## Структура и особенности фида

Проверена копия от 10.11.2026: 1 770 записей, 166 категорий, 4 360 ссылок на изображения. Все цены положительные. 334 записи имеют `available=true`, 1 436 — `false`. Фид динамический, числа могут измениться.

| XML | miniShop3 |
| --- | --- |
| `vendorCode` | `msProductData.article`, как строка с ведущими нулями |
| `name` | `pagetitle` |
| `categoryId` и `categories/category@parentId` | Категория товара и дерево `msCategory` внутри `root_id` |
| `price`, `oldprice` | `price`, `old_price` |
| `currencyId=RUR` | Принимается как RUB без пересчёта цены |
| `description` | `content` |
| `weight` | `msProductData.weight`, кг |
| `param name="Вес, кг"` | Характеристика; также источник `weight`, если тег `weight` отсутствует |
| `param` | Определения `msOption`, связи с категориями и значения `msProductOption` |
| `picture` | Штатная галерея miniShop3 и её миниатюры |
| `available` | Опция `memorials_available`, `1` или `0` |
| `barcode` | Опция `memorials_barcode`, без потери ведущих нулей |
| `dimensions` | Опция `memorials_dimensions`, исходные габариты Д/Ш/В в сантиметрах |

Названия, значения и единицы характеристик сохраняются из фида: вид камня, цвет, форма, длина, ширина, толщина, вид памятника, ориентация и другие. Ключ параметра — `memorials_` + первые 24 символа SHA-256 исходного имени; в менеджере отображается исходная подпись. Размеры в `param`, подписанные в мм, остаются в мм; `dimensions` в см хранится отдельно. Сложные значения вроде `50(60)` остаются строками, не преобразуются в число.

Числового складского остатка в текущем фиде нет. Наличие не превращается в количество: существующий `stock` сохраняется, у нового товара действует штатное значение miniShop3, обычно 0. Если в будущем появится количество, оно обновится по `stock_tags`/`stock_params`. Явный числовой ноль переносится. `available=false` не снимает товар с публикации автоматически; шаблон витрины может использовать `memorials_available` для отображения наличия.

## Повторяющиеся артикулы

В проверенном фиде у 19 артикулов по две разные записи: 38 записей конфликтуют. Они отличаются моделью, материалом, размером, ценой или категорией и не должны перезаписывать друг друга.

По умолчанию `duplicate_policy=skip`: **пропускаются все записи каждого повторного артикула**, включая первое вхождение. Обрабатываются остальные 1 732 записи. Перечень конфликтов доступен в `duplicate-articles.csv`, `validation.json` и событии `validated` журнала. Артикулы проверяются без учёта регистра. CSV следует открывать с текстовым типом столбца `article`, чтобы табличный редактор не убрал ведущие нули.

При `duplicate_policy=error` импорт прервётся до записи, пока дубликаты не исправлены в источнике. Модуль не дописывает ID к артикулу и не выбирает одну из записей произвольно. После исправления артикулов у поставщика следующие запуски смогут обработать эти товары. Число 1 732 описывает проверенную копию, а не жёсткий лимит.

Если в базе MODX уже есть несколько товаров с одним артикулом, такой товар пропускается с `product_error`. Товар с единственным совпадением в корзине MODX тоже пропускается. Поиск идёт в выбранном `context`; внутри него `root_id` не ограничивает поиск по артикулу. При изменении артикула поставщиком создаётся новый товар.

## Правила обновления

Категории сопоставляются по `properties.memorialsxml.source/category_id`, независимо от alias; `source_key` нельзя менять после первого запуска. Категории магазина автоматически по названию не объединяются с импортируемыми. При обновлении переносятся название категории и родитель; шаблон/публикация сохраняются.

У товаров обновляются название, описание, родительская категория и присутствующие поля данных. Ручные alias, шаблон и статус публикации существующего товара сохраняются. Новые товары публикуются по `publish_new_products`. `zero_price_policy=preserve` сохраняет прежнюю цену при нуле в источнике, новые товары без цены создаёт неопубликованными. `zero_price_policy=import` переносит и нулевую цену буквально. В проверенной копии нулевых цен нет.

Описание сохраняется как текст с переносами строк: сложная HTML-вёрстка поставщика не переносится, HTML/MODX-теги нейтрализуются. В шаблонах экранируйте значения характеристик при выводе, как пользовательский текст.

Присутствующие характеристики обновляются; отсутствующие в следующем фиде и посторонние опции магазина сохраняются. Изображения добавляются через `MiniShop3\Processors\Gallery\Upload`; дубликаты определяются штатным хешем miniShop3. Старые изображения не удаляются, назначенная обложка не заменяется принудительно. На повторном запуске картинки скачиваются для сравнения хеша. Исчезнувшие из фида товары/категории не удаляются и не снимаются с публикации.

## Журнал, ошибки и ограничения

Журнал — JSON Lines в stdout. События: `validated`, `category`, `product`, `duplicate_skipped`, `product_error`, `image_error`, `summary`, `fatal`.

Коды завершения:

- `0`: успешная проверка или импорт без ошибок/пропусков;
- `1`: ошибка конфигурации, загрузки, XML или дерева категорий;
- `2`: отдельные товары/картинки завершились с ошибками либо в ходе импорта были пропущены конфликтные записи.

`--inspect` возвращает `0` при корректном XML с разрешённым пропуском дубликатов, но содержит все конфликты в отчёте. При `duplicate_policy=error` они дают код `1`.

XML сначала копируется во временный снимок и целиком проверяется до записи. Неизвестные категории, циклы, некорректные цены или недопустимые домены изображений останавливают запуск. Внешние DTD не загружаются, внутренние DTD/entities запрещены. Сайт возвращает 403 на нестандартный User-Agent. Поэтому по умолчанию используется стандартный агент установленной cURL; при необходимости его можно задать через `http_user_agent`. Проверены загрузка фида и одного изображения этим HTTP-клиентом. Домены перечислены в `allowed_hosts`; HTTP-редиректы запрещены, используйте окончательный URL.

Локальная и MySQL-блокировка защищают от параллельных запусков этого модуля. Они не координируют сторонние импортеры и ручное создание товаров. Уникальный индекс на артикул не добавляется, схема базы не меняется.

Запись товара, характеристик и файлов не является единой транзакцией. Ошибка отдельного товара не мешает обработке остальных; ошибка категории прерывает импорт. После ошибки возможны частично заполненные товары. Повторный запуск дополняет данные, но плагины MODX могут иметь собственные побочные эффекты.

## Исправление 1.0.1: привязка характеристик

Исправлена ошибка `Duplicate entry '0-0'` при записи `ms3_category_options`. У модели `msCategoryOption` поля `option_id` и `category_id` составляют первичный ключ. Обычный вызов xPDO `fromArray()` пропускал оба поля, оставляя нули. Теперь ID задаются явно через `set()`, а перед записью проверяются положительные значения.

Для обновления с 1.0.0 достаточно заменить `src/Importer.php` файлом из версии 1.0.1. Существующий `config.php` сохраняется. Затем повторите пробный импорт 10 товаров без изображений через прежний код Console или CLI: частично сохранённые товары будут найдены по артикулу и дополнены характеристиками.

Предупреждения PHP 8.5 (`ReflectionProperty::setAccessible`, `null as an array offset`), сообщения Translitor `Undefined array key "ru"` и сообщения кеширования лексиконов относятся к установленным зависимостям/дополнениям сайта. Исправление связи характеристик не устраняет их. Изменять ядро MODX, сторонние плагины или удалять строки базы для применения этого исправления не требуется.

Добавлен тест с поведением xPDO по умолчанию для составных ключей, проверкой положительных ID и отсутствия повторных связей при повторном импорте. Он воспроизводит ошибку на 1.0.0 и проходит после исправления. Дополнительно проверен реальный класс `xPDOObject` из ветки xPDO 3.x без подключения к базе:
