# TssXml 1.2.0 — порционный импорт товаров ТСС в miniShop3

Для MODX Revolution 3.2.4-pl, miniShop3 1.14.3-beta2, PHP 8.5. Источник по умолчанию: https://www.tss.ru/bitrix/catalog_export/yandex_800463.xml.

## Опубликовать товары ТСС и затем загрузить картинки (1.2.0)

Обновите файлы модуля с сохранением config.php и кеша позиции. В Console выполните без `<?php`:

```php
$publishBatchSize = 20;
$imageBatchSize = 1;
$maxSeconds = 15;
$imageTimeout = 20;
$useCoreParser = true;
require MODX_CORE_PATH . 'components/tssxml/console-publish-images.php';
```

Первый этап публикует существующие неопубликованные товары, второй автоматически переходит к отдельной очереди изображений. Вкладку Console нужно держать открытой. Ранее импортированные карточки, цены и характеристики повторно не загружаются. Снимок исходной основной очереди не сбрасывается.

Публикуются только ресурсы класса msProduct в config.context, не находящиеся в корзине, с метаданными `properties.tssxml.source`, равными config.source_key. Прочие товары сайта, категории, другие контексты и источники не публикуются. В выборку входят товары с нулевой ценой: пользователь явно разрешает их публикацию этим запуском. Цены кодом публикации не меняются, zero_price_policy переписывать не нужно. В следующих импортах существующий статус публикации сохраняется.

Для публикации используется штатный процессор `MODX\Revolution\Processors\Resource\Publish`, включая его проверки прав, alias, события и журнал. Как и обычная команда MODX «Опубликовать», он устанавливает published=1 и сбрасывает даты отложенной публикации/снятия. Категории/корневая категория автоматически не публикуются. На видимость также влияют опубликованность родителей и правила шаблона.

Список ID неопубликованных товаров фиксируется при начале этапа в `core/cache/tssxml-publish/<идентификатор>/state.json`. Позиция сохраняется после каждого результата. Перед каждой публикацией принадлежность источнику, контекст и корзина проверяются повторно. Изменившие область ресурсы пропускаются. Ошибка одного ресурса сохраняется и не блокирует остальные; список ошибок выводится. Завершённый этап сам по себе не начинается повторно. Новые неопубликованные товары, созданные после формирования списка, в этот снимок не входят.

После публикации, даже если остались отдельные ошибки публикации, начинается загрузка картинок существующих товаров из фида через `tssxml-images-only`. Уже завершённая ранее очередь картинок не сбрасывается; для её ошибок есть console-retry-images.php. Наличие ошибки публикации не означает автоматического исправления этой карточки этапом картинок.

Параметр useCoreParser=true подставляет штатный modParser только в запросах этапа изображений, чтобы проверить обход ранее выявленного зависания Media Source в разборе свойств. Системные настройки парсера в базе не сохраняются; этап публикации использует обычный парсер сайта. Этот обход не подтверждён интеграционным запуском на сервере пользователя. Для сохранения пользовательского парсера в запросах картинок задайте false. Он не устраняет плагины OnParseDocument, если причина в них.

Если нужно заново сформировать список публикации после завершения этапа, сначала остановите авторежим, сохраните отчёт и удалите только state.json из папки tssxml-publish, затем повторите запуск. Не удаляйте снимки основного импорта/картинок и не сбрасывайте активный этап. Штатная MySQL-блокировка защищает публикацию от параллельного запуска других режимов TssXml.

## Обновление с 1.0.0

Обновите файлы в `core/components/tssxml/`, сохранив свой `config.php`. Новые параметры автоматически дополняются значениями по умолчанию; прежний формат конфигурации поддерживается. В config.php должен быть заполнен `root_id` — ID категории miniShop3, внутри которой создаётся дерево поставщика.

Исправление составных первичных ключей `msCategoryOption` включено: `category_id` и `option_id` задаются через set(), поэтому известная ошибка `(0,0)` не требует ручной правки файла.

В 1.0.0 позиции для продолжения не было. Первый запуск новой версии обходит снимок сначала, находит ранее сохранённые товары по артикулу и обновляет их. Названия метаданных `properties.tssxml`, source_key и ключи характеристик сохранены для сопоставления категорий и опций. Не меняйте source_key после установки. Если в базе несколько товаров с одним артикулом, они отмечаются ошибкой, а не объединяются.

## Рекомендуемый запуск через Console: все товары без картинок

Вставьте без `<?php` и нажмите «Выполнить» один раз:

```php
$_SESSION['Console']['completed'] = true;
$loadImages = false;
$batchSize = 20;
$maxSeconds = 15;
require MODX_CORE_PATH . 'components/tssxml/console-auto.php';
```

Console автоматически отправляет следующие запросы до завершения обхода. Каждый запрос обрабатывает ограниченную порцию, сохраняет позицию после каждого товара и возвращает управление. Вкладку нужно держать открытой. При транспортной ошибке/обрыве нажмите «Выполнить» снова с тем же кодом. Бесконечного PHP-цикла внутри одного запроса нет. Штатный механизм повторения Console — `$_SESSION['Console']['completed']`.

По умолчанию в Console изображения выключены, чтобы их обработка не задерживала загрузку карточек. Уже загруженные фотографии не удаляются. По окончании будет фаза `done` либо `done_with_errors`; при ошибках проверяйте отчёт. Автоматическое повторение останавливается по завершении или ошибке запуска.

Остановка:

```php
$_SESSION['Console']['completed'] = true;
```

Текущий отправленный запрос может завершиться после закрытия вкладки. Перед выполнением другого произвольного кода Console после закрытия авторежима выполните строку остановки, чтобы сбросить оставшийся флаг повторения.

## Позиция и повторные запуски

Снимок XML и state.json сохраняются в `core/cache/tssxml-batch/<идентификатор>/`. Точный путь выводится после каждой порции. Позиция сохраняется после каждой попытки обработки товара, в том числе при зарегистрированной ошибке. Список ошибок остаётся в state.json. Изменения текущего фида поставщика не меняют уже обрабатываемый снимок. Не очищайте кеш MODX во время цикла.

Старый импорт должен завершиться/быть остановлен до начала нового: общая MySQL-блокировка защищает от параллельного запуска версий 1.0.0/1.1.0. Закрытие страницы браузера не гарантирует завершения старого PHP-процесса.

Чтобы начать новый цикл со свежим XML, сначала остановите авторежим. Один раз выполните:

```php
$_SESSION['Console']['completed'] = true;
$loadImages = false;
$resetImport = true;
$batchSize = 1;
require MODX_CORE_PATH . 'components/tssxml/console-batch.php';
```

Затем снова запустите console-auto.php. Сбрасывается только позиция/снимок; товары и галерея не удаляются. В авторежиме resetImport принудительно выключен, чтобы не начинать цикл заново в каждом запросе.

## Картинки — отдельно после товаров

Загрузка использует штатную галерею и Media Source miniShop3. Ранее на сервере пользователя зафиксировано зависание разбора свойств Media Source при вызове MODX-парсера; его причина/устранение не подтверждены. Порционная архитектура не устраняет эту проблему ядра/дополнений. Сначала завершите загрузку карточек без изображений.

Для исправно работающей галереи отдельный режим картинок:

```php
$batchSize = 1;
$maxSeconds = 15;
$imageTimeout = 20;
require MODX_CORE_PATH . 'components/tssxml/console-images-only.php';
```

Он сразу начинает фазу images и обрабатывает только существующие товары. Карточки и категории не создаются/не изменяются. Отдельная позиция: `core/cache/tssxml-images-only/<идентификатор>/`. Не найденные по артикулу товары пропускаются с отчётом. Картинки добавляются с проверкой штатного хеша miniShop3; старые изображения сохраняются, точное зеркалирование галереи не выполняется.

Повтор только ошибочных URL после завершения отдельной очереди:

```php
$imagesOnly = true;
$batchSize = 1;
$imageTimeout = 25;
require MODX_CORE_PATH . 'components/tssxml/console-retry-images.php';
```

При повторе успешно исправленная ошибка удаляется из текущего списка, история сохраняется. Цикл прекращается после прохода, даже если остались ошибки. Настройка imageTimeout ограничивает только сетевое ожидание, а maxSeconds проверяется между операциями. Создание миниатюр может выйти за эти пределы.

## Данные и правила

- Создание/обновление по строковому артикулу в контексте config.context. Приоритет vendorCode, иначе param «Артикул»; ведущие нули сохраняются. Товар в корзине MODX пропускается с ошибкой.
- Дерево категорий создаётся внутри root_id; существующие импортированные категории сопоставляются по метаданным. Неизменившиеся категории повторно не сохраняются.
- Цена/oldprice, описание, числовой остаток при наличии, характеристики, вес при наличии weight/«Вес, кг», штрихкоды/габариты при наличии. Характеристики сохраняются как msOption/msCategoryOption/msProductOption с прежними ключами tss_<хеш имени>.
- Описание: param «Описание товара», иначе description. HTML превращается в текст с переносами, MODX-теги нейтрализуются.
- Шаблон, alias и статус публикации существующего товара сохраняются. Исчезнувшие из фида товары/категории не удаляются.
- Существующие посторонние опции сохраняются; отсутствующие в следующем фиде характеристики не удаляются.

Проверенный 14.11.2026 фид: 3 028 товаров, 173 категории, 5 253 ссылки на картинки, все артикулы уникальны. Числовых остатков нет — existing stock не затирается, available сохраняется в tss_available. При появлении количества оно читается по stock_tags/stock_params. RUR принимается как RUB; конвертации курсов нет. Пустая валюта допускается только при нулевой цене.

У 1 708 записей нулевая цена. По умолчанию zero_price_policy=preserve: прежняя цена существующего товара сохраняется, новые без цены создаются неопубликованными. Поэтому завершённый импорт 3 028 карточек не означает 3 028 опубликованных товаров на витрине. Для буквального переноса нулей есть zero_price_policy=import.

В случае дубликатов в XML duplicate_policy=error останавливает импорт до записи. Можно явно выбрать skip: тогда исключаются все записи каждого повторного артикула. В текущей проверенной копии конфликтов нет.

## CLI и требования

```bash
php import.php --config=/path/config.php --inspect --no-images
php import.php --config=/path/config.php --dry-run --no-images
php import.php --config=/path/config.php --no-images
```

CLI без --no-images использует параметр images конфигурации и выполняет полный запуск одним процессом, а не порциями Console. Для автоматизации без открытого браузера можно использовать CLI/cron.

Нужны XMLReader, SimpleXML, mbstring, cURL, fileinfo, PDO MySQL и зависимости установленного MODX/miniShop3. Пользователь PHP должен иметь доступ к MODX, временному каталогу, кешу позиции и Media Source. Новых таблиц модуль не создаёт. Файл config.php использует существующее подключение MODX. Обработчики сохранения MODX могут иметь свои побочные эффекты. Ресурс, характеристики и файлы не объединяются в одну общую транзакцию; повторный запуск дополняет частично сохранённые данные.

## Проверки публикации 1.2.0

Добавлены тесты ограниченной публикации: нулевая/ненулевая цена без её изменения; исключение других поставщиков/контекстов, корзины, категорий и товаров без метки; сохранённый курсор; повторная проверка области между запросами; продолжение после ошибки; отсутствие повторного запуска завершённого списка; отсутствие полной очистки кеша. Проверен двухэтапный протокол Console: публикация до картинок, автоматическое продолжение, завершение, остановка ошибки и отсутствие действий без sudo. Вызовы процессора/галереи в этих сценариях имитируются. Настоящий процессор публикации сверён с исходниками MODX v3.2.4-pl; на сервере пользователя публикация и новый сценарий не выполнялись.
