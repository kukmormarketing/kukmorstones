# TssXml — импорт YML/XML в miniShop3

CLI-модуль для MODX Revolution 3.2.4-pl, miniShop3 1.14.3-beta2 и PHP 8.5.
Версия 1.0.0. Это самостоятельный CLI-модуль; интерфейс в менеджере MODX и transport-пакет в эту версию не входят.

## Возможности

- Источник: абсолютный путь к XML на сервере или HTTP(S)-ссылка.
- Создание/обновление товаров по артикулу в выбранном контексте MODX.
- Артикул: `vendorCode`, а при его отсутствии — `<param name="Артикул">`. Ведущие нули сохраняются.
- Создание/обновление дерева категорий внутри существующей категории магазина.
- Перенос цены, oldprice, описания, числового остатка при наличии в XML, изображений и характеристик.
- Характеристики создаются как `msOption`, привязываются к категории через `msCategoryOption`, значения сохраняются как `msProductOption`.
- Потоковое чтение XML; перед записью проверяется весь файл, включая уникальность артикулов и дерево категорий.
- `--inspect` проверяет XML без MODX; `--dry-run` дополнительно проверяет сопоставление с базой MODX без записи товаров/категорий.
- Журнал JSON Lines в stdout, коды завершения для cron, локальная и MySQL-блокировка одновременных запусков.

## Установка

1. Распакуйте каталог `tssxml` на сервере, например в `/var/import/tssxml/`. Composer для самого модуля не требуется: используется установленный MODX/miniShop3.
2. Скопируйте `config.example.php` в `config.php`.
3. Укажите в `config.php`:
   - `modx_base_path`: абсолютный путь к корню сайта, где лежит `config.core.php`;
   - `root_id`: ID существующей категории miniShop3, внутрь которой нужно импортировать дерево поставщика;
   - `manager_user_id`: ID активного пользователя MODX с `sudo=true`;
   - при необходимости `product_template` и `category_template`;
   - `source`: ссылка или абсолютный путь к XML.
4. Запускайте CLI от пользователя, имеющего доступ к файлам MODX, временному каталогу и медиахранилищу miniShop3. Для изображений должен быть настроен штатный Media Source miniShop3 и генерация миниатюр.

Расширения PHP: XMLReader, SimpleXML, mbstring, cURL, fileinfo, а также расширения установленного MODX/miniShop3, включая PDO MySQL и обработку изображений. Версия PHP CLI должна соответствовать PHP сайта.

Не требуется запускать отдельный SQL или менять таблицы: используются штатные модели/процессоры miniShop3.

## Первый запуск

```bash
cd /var/import/tssxml
cp config.example.php config.php
# Отредактируйте config.php перед командами ниже.

# Только проверка фида, база MODX не нужна:
php import.php --config=/var/import/tssxml/config.php --inspect

# План создания/обновления по данным вашей базы:
php import.php --config=/var/import/tssxml/config.php --dry-run > plan.jsonl

# Пробная запись первых 10 товаров без изображений:
php import.php --config=/var/import/tssxml/config.php --limit=10 --no-images > trial.jsonl

# Полный импорт, включая изображения:
php import.php --config=/var/import/tssxml/config.php > import.jsonl
```

Пробную запись и полный первый импорт выполните на копии сайта. `--limit=10` ограничивает число товаров, но дерево категорий обрабатывается целиком; весь XML всё равно проверяется до начала записи.

Для локального XML:

```bash
php import.php --config=/var/import/tssxml/config.php --source=/var/import/feed.xml
```

Для cron используйте ту же команду с абсолютными путями к PHP и конфигурации, перенаправив stdout/stderr в журнал. Блокировки уже встроены. Повторять запуск после ошибок можно: завершённые товары будут найдены по артикулу.

Коды завершения:

- `0`: успешно, либо успешно выполнена проверка/план;
- `1`: ошибка конфигурации, источника, валидации или структуры импорта;
- `2`: отдельные товары или изображения завершились с ошибками; подробности в `product_error` и `image_error`.

## Особенности предоставленного фида ТСС

Проверенная копия: `https://www.tss.ru/bitrix/catalog_export/yandex_800463.xml`, загружена 09.11.2026. Это динамический фид, его состав меняется.

- 3 028 товаров, 173 категории, 5 253 ссылки на изображения.
- Все артикулы заполнены и уникальны; они находятся в параметре `Артикул`.
- Числовых складских остатков нет. Есть только `available=true/false`.
- У 1 708 товаров цена равна нулю; у части из них также пустой `currencyId`.

**Остатки.** `available` сохраняется в опцию `tss_available` со значением `1` или `0`. Оно не преобразуется в выдуманное количество. Если числового остатка нет, существующий `stock` не изменяется; у нового товара действует штатное значение miniShop3, обычно 0. Для реальных остатков поставщик должен добавить количество. Поддерживаемые теги и имена параметров задаются в `stock_tags` и `stock_params`. Явный остаток `0` переносится.

**Нулевая цена.** По умолчанию `zero_price_policy=preserve`: ноль не затирает известную цену существующего товара, новый товар с нулевой ценой создаётся неопубликованным. После появления положительной цены она обновится, но публикация уже существующего товара остаётся под контролем редактора. Для буквального переноса нулевых цен задайте `zero_price_policy=import`. В этом режиме публикация новых товаров зависит только от `publish_new_products`.

Пустая валюта допускается только при нулевой цене. Иная валюта без конвертации отклоняется.

## Сопоставление и правила обновления

Товары ищутся по `msProductData.article` в `context`, включая удалённые ресурсы. Если найдено больше одного совпадения либо единственный товар находится в корзине MODX, товар пропускается с ошибкой. Отдельной связи по offer ID нет: изменившийся артикул создаёт новый товар.

Категории сопоставляются по метаданным `properties.tssxml.source/category_id`. Поэтому переименование категории или смена alias в MODX не создаёт дубликаты. Существующие категории магазина автоматически по названию не объединяются с категориями поставщика. Не меняйте `source_key` после первого импорта.

При обновлении товара переносятся название, родительская категория, описание и присутствующие в фиде поля данных. Шаблон, alias и статус публикации сохраняются. Товары и категории, исчезнувшие из фида, не удаляются и не снимаются с публикации.

Подробное описание берётся из `param name="Описание товара"`, иначе из `description`. Входящий HTML превращается в текст с переносами строк; MODX-теги нейтрализуются. Результат записывается в `content`. Это не сохраняет сложную HTML-вёрстку поставщика.

Все непустые `param`, кроме артикула и двух полей описания, становятся характеристиками. Повторные значения сохраняются списком. Ключ: `tss_` + первые 24 символа SHA-256 исходного названия. Название и единицы измерения видны в менеджере. Существующие значения присутствующих характеристик заменяются; отсутствующие в следующем фиде характеристики сохраняются. Другие опции магазина сохраняются. В шаблоне витрины экранируйте значения характеристик как обычный пользовательский текст.

Изображения загружаются через штатный `MiniShop3\Processors\Gallery\Upload`; миниатюры создаёт miniShop3. Дубликаты определяются штатным методом хеширования miniShop3. Импорт добавляет отсутствующие изображения и сохраняет старые; точного зеркалирования галереи и удаления изображений в этой версии нет. При изменении содержимого картинки будет добавлен новый файл, уже назначенная обложка не заменяется принудительно. На повторном запуске изображения скачиваются для проверки хеша.

## Ошибки и ограничения

XML сначала копируется в отдельный временный снимок. Некорректный XML, дубли артикулов, неизвестная категория, цикл категорий или недопустимый URL изображения останавливают импорт до записи каталога. Не загружаются внешние DTD; внутренние DTD и XML entities запрещены. Доступные домены задаются в `allowed_hosts`. HTTP-редиректы запрещены: указывайте окончательную ссылку.

После начала записи ошибка одного товара не останавливает остальные. Ошибка категории прерывает импорт. Запись ресурса, его характеристик и файлов не объединена в общую транзакцию: после ошибки возможны частично заполненные товары, а плагины MODX могут иметь собственные побочные эффекты. Повторный запуск дополняет данные. `--dry-run` не вызывает процессоры сохранения и не скачивает изображения, поэтому не гарантирует успешность записи/генерации миниатюр; инициализация MODX может создавать свой системный кеш.

При поиске товаров учитывается выбранный контекст. Проверка дубликатов в самом XML игнорирует регистр; сравнение артикула в базе дополнительно зависит от её collation. Для одного артикула не предусмотрены варианты товара.

Запуски этого модуля блокируют друг друга на уровне сайта/базы. Сторонние импортеры и ручное создание товаров такими блокировками не управляются; уникального индекса на артикул miniShop3 не добавляется.
